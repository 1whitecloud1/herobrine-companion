Herobrine Companion — 单模组兼容与启动安全模式

一、安装

现在只发布、安装一个 Herobrine Companion JAR，模组 ID 仍是 herobrine_companion。
Accessories、Armourer's Workshop、Epic Fight、Simple Hats、WaveyCapes 的兼容实现已内置。
WOM、Nightfall、Avalon 的相关桥接也随内置 Epic Fight 兼容提供。
这些第三方模组本身仍由玩家按需安装，不会被嵌入本体 JAR。

升级时不要再同时安装旧的 herobrine-companion-compat-*.jar。
本体与第三方模组必须匹配 Minecraft 版本和加载器：Forge 1.20.1 与 NeoForge 1.21.1 不可混用。

二、源码与构建

1.20.1：src/main/java/com/whitecloud233/modid/herobrine_companion/compat/
1.21.1：src/main/java/com/whitecloud233/herobrine_companion/compat/

这两个目录下直接保留 accessories、ArmourerWorkshop、epicfight、simplehats、waveycapes。
compat/mixin/ 保存第三方注入；compat/safety/ 保存启动检查和错误隔离。
api/compat/ 是本体的轻量调用边界，只暴露本体、原版和加载器类型。
不再使用 src/compat/java，也没有单独的 :compat Gradle 子项目。

在相应版本仓库根目录执行：
  .\gradlew.bat build

只生成 build/libs/ 下的本体 JAR（普通构建的安全版）。
-Pfull=true 仍只生成对应完整版本体；它与兼容启动安全模式是两个不同开关。

三、启动前开关

启动时会创建游戏目录下：
  config/herobrine_companion-compat.properties

示例：
  safeMode=false
  accessories=true
  armourers_workshop=true
  epicfight=true
  simplehats=true
  waveycapes=true
  wom=true
  efn=true
  epic_fight_avalon=true

把某项设为 false，仅关闭 Herobrine Companion 对该模组的集成，不卸载第三方模组。
设 safeMode=true 会关闭以上全部集成。退出游戏后编辑，重新启动才生效。
Epic Fight 被关闭或因检查失败停用后，它的 WOM / Nightfall / Avalon 扩展桥也不启用。
这些开关不影响烹饪、Curios、JEI、KubeJS、Patchouli、GeckoLib 等其他集成。

如果游戏尚未到达配置文件创建阶段，可在启动器的 JVM 参数中加入：
  -Dherobrine.compat.safeMode=true

或只关闭其中一项：
  -Dherobrine.compat.epicfight=false
  -Dherobrine.compat.accessories=false

JVM 参数的优先级高于配置文件。修复后移除对应参数并重启。
不要把这些 JVM 参数当作游戏命令输入，也不要与 Gradle -P 参数混用。
服务端与客户端使用相同配置更稳妥；纯客户端披风/帽子显示可以单独关闭。

四、哪些错误会自动隔离

- 目标模组未安装时，不加载对应实现。
- 支持范围之外的版本停用对应集成，不再仅因为该兼容的版本范围而阻止加载器启动。
- 应用兼容 Mixin 前检查目标字节码，包括方法、Shadow 字段和注入调用点。
- 检查不通过时跳过该组集成及其 Mixin。
- 专用兼容数据包、物品皮肤按检查结果加入资源集；禁用后不再自动启用它们。
- 受保护的反射调用、事件回调和帽子/饰品/披风渲染层遇到可恢复错误时，记录并停用该项，
  不在下一帧或下一次调用中反复重试。
- Hero 的 Epic Fight tick/换装备等受保护入口失败后，移除该补丁自己的战斗目标，
  本体的原生战斗与渲染回退可以继续接管。
- OutOfMemoryError 等虚拟机致命错误不会被吞掉。

日志中搜索：
  HerobrineCompanion/Compat
  Disabled Herobrine integration

会给出模组 ID、版本检查或失败阶段。修复配置/目标版本之后重启恢复。

五、明确边界

这不是热加载，也不是所有崩溃都能恢复。
已应用的 Mixin、冻结的注册表和外部模组自己的全局状态不能保证在运行中撤销。
预检之后其他模组再次改变注入点、已经发生的部分注册、第三方自身崩溃或加载器错误，
仍可能阻止启动。兼容 Mixin 保留严格失败要求，不用全局忽略错误来掩盖坏状态。

启动安全模式优先用于排查这些情况：先关闭本模组集成进入游戏，再核对版本与日志。
如果第三方模组本身就无法启动，关闭本模组兼容不能修复该第三方模组。
数据包关闭不会主动清除本体保存的 Accessories 装备备份；存档修改前仍建议备份世界。

六、开发验证

  .\gradlew.bat verifyCompatSafety
  .\gradlew.bat verifyCompatAbsent
  .\gradlew.bat verifyBundledCompat

分别检查开关/失败隔离与 Mixin 字节码契约、未安装目标模组时的回退，以及最终单模组 JAR。
这些检查随 build 执行；它们不等同于所有模组组合的实际客户端/独立服务器联机测试。

开发环境 -PwithCompat=false 现在只表示不加入默认的相关第三方测试依赖，
不会从发布 JAR 移除兼容代码，也不会生成第二个 JAR。
-PenableEpicFightCompat、-PenableAccessoriesRuntime、-PenableCosmeticRuntime
同样只控制开发运行依赖。运行时是否启用请使用上述 properties 文件或 JVM 参数。
